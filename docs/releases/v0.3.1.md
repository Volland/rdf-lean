LeanRDF 0.3.1 aligns the statement-graph format with tiramemsu, which now writes it itself (`tm export --format sg-nt12`). It also checks tiramemsu's output against LeanRDF's definition, byte for byte.

## Format change

Valid time is now exported as `tm:validFromMs` and `tm:validToMs` (`xsd:integer` epoch milliseconds), not `tm:validFrom` and `tm:validTo`. In tiramemsu's SPARQL and Cypher, `tm:validFrom` and `tm:validTo` are virtual predicates with `xsd:dateTime` values, so v0.3.0 gave one IRI two datatypes. `WellFormed` reserves the new names instead of the old ones. The transaction clocks are unchanged.

Files written by v0.3.0 that carry valid time decode only after the rename:

```sh
sed -e 's/tm:validFrom>/tm:validFromMs>/' -e 's/tm:validTo>/tm:validToMs>/' old.nt > new.nt
```

## tiramemsu cross-check

- `statements/StatementsTests/data/tm/` holds eight exports recorded from tiramemsu's tests: a route and its distance, a superseded distance in four views, a statement added and retracted in one transaction, and canonical string escapes. `lake test` decodes each one in its view and requires the re-export to match it byte for byte.
- tiramemsu's route export is byte-identical to LeanRDF's hand-written golden. The "pending tm cross-check" mark is gone.
- `scripts/statements-tm-record.sh TIRAMEMSU` records the files again from a tiramemsu checkout.

## What is proven and what is trusted

Unchanged from 0.3.0. Every theorem is checked by Lean's kernel, with no `sorry` and only `propext`, `Quot.sound` and `Classical.choice`. The cross-check is a test, not a proof about tiramemsu's Rust code. What it proves is narrower: whatever tiramemsu writes in the recorded cases is exactly the export of a well-formed statement graph (`toRDF_decode`).
